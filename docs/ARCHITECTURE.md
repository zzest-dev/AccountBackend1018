# Архитектура и протокол

```text
Android 10.18 + payload APKPatcher1018
        |
        | TCP / штатный аккаунтный конверт
        v
Transport -> Router -> Store / Commerce / Missions -> SQLite
```

Клиентская `BackendActivity` читает адрес из `backend.txt` и запускает C++-инициализацию в Unity-потоке. Payload через Dobby перехватывает выбор зеркала и создание аккаунтных запросов. Запросы отправляются на выбранный IPv4 по TCP, исходные сериализаторы и игровые ресурсы сохраняются. Изменения APK и проверки описаны в отдельном репозитории патчера.

## Состав C#-сервера

| Файл | Ответственность |
| --- | --- |
| `Program.cs` | Конфиг, TCP listener, лимит 128 подключений и остановка |
| `Transport.cs` | Framing, кодировка строк, таймауты и ответы |
| `Router.cs` | Handshake, регистрация, сессии, маршруты и сборка Cloud-профиля |
| `Store.cs` | Схема БД, аккаунты, каталоги, инвентарь, профили и статистика |
| `SqliteDb.cs` | Небольшой адаптер нативного SQLite без отдельного ORM |
| `Commerce.cs` | Проверка покупок и оплаты тюнинга, транзакции и повторы |
| `Missions.cs` | Старт и завершение миссий, проверки результата и награды |
| `Multiplayer.cs` | Интерфейсы и явные заглушки будущего мультиплеера |

## TCP-конверт

Каждое сообщение начинается с длины полезной нагрузки: **Int32 big-endian**, допустимо от 1 до 1 048 576 байт. Внутри кадра числовые поля little-endian. Строка: длина UTF-8 в Int32 little-endian, затем байты без завершающего нуля.

Первый клиентский кадр содержит Int32 со значением `8`, строку проверки транспорта и строковое значение состояния bend. Реализация проверяет версию и границы кадра, читает обе строки, но не использует их как доказательство подлинности клиента. Успешный ответ — кадр с четырьмя нулевыми байтами.

Запрос после приветствия:

| Поле | Тип |
| --- | --- |
| Версия конверта | Int16, `8` |
| ID запроса | UInt32 |
| Маршрут | Строка |
| Таймаут клиента | Byte |
| Тип тела | Строка, обработчики ожидают `json` |
| Тело | Строка JSON |

Ответ:

| Поле | Тип |
| --- | --- |
| Маркер | Int16, `15777` |
| ID запроса | UInt32 |
| Код ошибки | Int16, `0` при успехе |
| Сообщение ошибки | Строка |
| Тип тела | `json`, `text` или `none` |
| Тело | Строка JSON/text; отсутствует при `none` |

Это не HTTP API. Обращение к URL в браузере или обычный HTTP-запрос не проверяет работоспособность протокола. Таймаут начального приветствия — 15 секунд, последующего чтения — 60 секунд.

## Маршруты

| Маршрут | Назначение |
| --- | --- |
| `/mirror/ping/` | Проверка доступности зеркала |
| `/mirror/hand_shake/`, `/main/hand_shake/` | GUID узла |
| `/main/open_connect/` | Краткоживущий `connect_id` |
| `/main/register/` | Гостевая регистрация |
| `/main/login/` | Вход по гостевому токену и выдача сессии |
| `/main/check_state/` | Проверка активной сессии |
| `/user/get_cloud_data/` | Профиль, гараж, цены и прогресс |
| `/sell/buy_items/` | Покупки и сохранение оплаченных изменений |
| `/user/check_nik_name/` | Проверка нового ника |
| `/user/try_apply_new_nik_name/` | Смена ника |
| `/stat/data/` | Приём статистики |
| `/Mis/start/`, `/Mis/complete/` | Попытки миссий и выдача наград |
| `/match/list/` | Пустой список серверов |
| `/match/try_connect_to_game_server/` | Заглушка, код 503 |

Прочие маршруты возвращают явную ошибку неподдерживаемого запроса. `IGameServerDirectory` и `IGamePacketBridge` оставляют границу для будущей реализации; `MirrorToUnet` и `UnetToMirror` выбрасывают `NotSupportedException`.

## Сохранение и повторы

Обработчики сериализуются блокировкой маршрутизатора. Покупки и начисления используют SQLite-транзакции. Для повтора операции используется хеш токена сессии и транспортного ID запроса. Повтор с тем же содержимым возвращает сохранённый результат, изменение содержимого под прежним ключом отклоняется. Новый ID покупки считается новой операцией и проходит обычную проверку баланса и владения.

Миссии дополнительно хранят состояние попытки и квитанцию завершения, чтобы повторный запрос результата не выдавал награду заново. Сервер проверяет доступность миссии, последовательность, длительность и позиции, но не симулирует саму гонку; данные результата поступают от клиента.
