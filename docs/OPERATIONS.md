# Настройка и данные

## Конфигурация

`server.json` по умолчанию читается из каталога программы, включая запуск через `dotnet run`. Файл копируется туда при сборке. Указывать собственный рабочий конфиг удобнее через `--config`.

| Поле | Значение |
| --- | --- |
| `listen_host` | IPv4 интерфейса или `0.0.0.0` для прослушивания всех IPv4-интерфейсов |
| `listen_port` | TCP-порт, по умолчанию 10118 |
| `database` | Путь к SQLite-файлу |
| `catalog_directory` | Каталог с ценами, миссиями и параметрами машин |
| `new_account.coins` | Монеты только для новых аккаунтов |
| `new_account.diamonds` | Кристаллы только для новых аккаунтов |

Относительные пути считаются от файла конфигурации. `--host` и `--port` имеют приоритет над конфигом. После правки конфигурации или каталогов перезапустите сервер.

## Каталог

- `data/catalog.json`: основной каталог предметов и цен.
- `data/extra-catalog.json`: дополнительные позиции и цены услуг.
- `data/car-configs/*.json`: определения автомобилей.
- `data/missions.json`: миссии и награды, включая 250 кристаллов за `Get Drugs`.

Формат этих файлов читают `Store`, `Commerce` и `Missions`. При запуске каталог загружается в базу; при изменении данных сервер повышает ревизию профилей, чтобы клиент получил обновление. Для изменения цен правьте JSON и проверяйте результат на копии базы. Уже купленные предметы и баланс не сбрасываются при обычной перезагрузке каталога.

## Аккаунты и резервная копия

SQLite содержит аккаунты, хеши гостевых токенов, инвентарь, сохранённые блоки профиля, квитанции покупок, попытки и прогресс миссий. Временные сессии находятся в памяти; после рестарта клиент заново входит со своим сохранённым гостевым токеном.

Для резервной копии остановите сервер через Ctrl+C и сохраните согласованный набор SQLite-файлов. У работающей базы могут быть файлы `-wal` и `-shm`: нельзя считать копию только основного файла полноценным бэкапом. Для копирования без остановки используйте SQLite backup API или штатную команду `.backup` клиента SQLite.

База Python-прототипа совместима с C#-сервером по схеме. Остановите Python-сервер, сделайте резервную копию, укажите путь к согласованной копии базы в `database` и запустите C#-сервер. Не запускайте обе реализации одновременно на одной базе. Существующие аккаунты не регистрируются заново и не получают повторно стартовый баланс.

Клиентские данные тоже важны: гостевой токен позволяет войти в прежний аккаунт. Удаление приложения или очистка его данных может удалить этот токен. Наличие одной серверной базы не означает, что чистая установка автоматически выберет прежний аккаунт.

## Границы развёртывания

Текущая реализация использует исходный TCP-конверт без TLS. Она подходит для частного сервера и контролируемого тестирования. Учетные данные и профиль требуют защищённого канала, если соединение проходит через недоверенную сеть. Автоматического внешнего входа, восстановления аккаунта по почте, административной панели и серверной симуляции миссий здесь нет.

Windows использует системную SQLite (`winsqlite3.dll`); Linux требует `libsqlite3.so.0`. Файл базы и каталоги должны быть доступны пользователю процесса. Логи ошибок содержат маршрут и код ошибки; не добавляйте гостевые и сессионные токены в публичные отчёты.
